# خريطة الحالة الفعلية لتطبيق Mirror Scorpion

**تاريخ التدقيق:** 6 أكتوبر 2026  
**المستودع:** `Mirorr_scorpion_v5`  
**نطاق التدقيق:** الكود النشط، الخدمات، الأصول، الاختبارات، CI، الخصوصية، والتوافق مع المتطلبات المعلنة.

## 1. الحكم التنفيذي

المشروع **تطبيق Flutter حقيقي يحتوي على وظائف عاملة**، وليس نموذج واجهة فقط. أقوى المسارات الحالية هي:

- الترجمة النصية المحلية عبر ML Kit بعد تنزيل نماذج اللغة.
- الحوار المحلي: تسجيل WAV ثم Whisper محلي ثم ترجمة محلية.
- استخراج PDF/TXT محلياً وإنشاء PDF مترجم للمشاركة أو الطباعة.
- لعبة شطرنج محلية مع محرك قانوني، مستوى تكيفي، قطع SVG، القطع المأسورة، ومؤثرات صوتية محلية.
- فقاعة Android مع مسار Accessibility صريح وقائمة تطبيقات مسموحة.

لكن التطبيق **لم يحقق بعد كل الوصف الأصلي**. الفجوات الرئيسية هي:

1. الصوت الناطق ليس محركاً كاملاً داخل التطبيق؛ `SystemTtsService` يعتمد على محرك Android المثبت.
2. الذكاء الاصطناعي المحلي للقصص غير موجود بعد؛ بطاقة القصص الحالية مكتبة محتوى محلية/فهرسة وحقل إنشاء، وليست مولداً ذكياً محلياً.
3. OCR الحالي يعلن صراحة أنه لاتيني فقط، لذلك العربية واللغات غير اللاتينية ليست مضمونة.
4. الفقاعة ومسار Accessibility يحتاجان اختبار APK على أجهزة Android فعلية، ولم يثبتا بعد على WhatsApp/Telegram بمصفوفة أجهزة.
5. التعريب غير مكتمل: توجد مئات النصوص العربية الثابتة داخل الواجهات، وعدة شاشات تفرض RTL حتى عند اختيار لغة إنجليزية.
6. أحدث CI ليس أخضر: تحليل الاختبارات يفشل في اختبار شاشة الشطرنج بسبب غياب `AppLocalizations` من بيئة الاختبار، ومسار APK يتوقف عند تثبيت NDK.

## 3. ما هو محلي فعلاً وما يحتاج شبكة

### محلي بعد التجهيز

- ترجمة ML Kit بعد وجود النموذج على الجهاز.
- كشف اللغة بعد تشغيل ML Kit.
- تسجيل الحوار إلى ملف مؤقت محلي.
- تفريغ Whisper محلياً بعد وجود النموذج.
- OCR للصورة على المنصة الأصلية.
- استخراج PDF/TXT حسب حدود المكتبات.
- شطرنج وقواعده وتكيف المستوى.
- أصوات الشطرنج WAV.
- قراءة TTS **ليست محلية بالكامل**؛ هي استدعاء لمحرك Android.

### يحتاج شبكة أو مصدر خارجي

- تنزيل Whisper من Hugging Face عند أول إعداد.
- تنزيل نماذج ML Kit عند أول زوج لغوي.
- جلب فهرس وحزم المحتوى من GitHub عند طلب المستخدم.
- ElevenLabs موجود ككود Gateway لكنه مغلق في الحالة الحالية؛ لا يجب اعتباره مساراً محلياً.
- Runware مجرد preflight/حاجز، وليس مولد فيديو عاملاً.

**الخلاصة:** التطبيق privacy-first في المعالجة، لكنه ليس zero-network؛ الشبكة مطلوبة للتجهيز والتنزيلات الاختيارية.

## 4. مشاكل CI الحالية

### فشل الاختبارات

آخر تشغيل للتحليل فشل في:

```text
test/chess_club_screen_test.dart
Null check operator used on a null value
_AppLocalizations.of(context)!_
```

السبب أن الاختبار كان ينشئ `MaterialApp` دون delegates/locales الخاصة بالتطبيق. تم إصلاح الاختبار محلياً بإضافة `AppLocalizations.localizationsDelegates` و`AppLocalizations.supportedLocales`.

### فشل APK

آخر تشغيل APK توقف في خطوة SDK/NDK أثناء:

```text
sdkmanager --install platforms;android-35 ndk;28.2.13676358
```

ظهر `yes: standard output: Broken pipe` ثم انتهت خطوة `sdkmanager` برمز 1. تم تعديل الإصدار محلياً إلى NDK مستقر واسع الانتشار:

```text
27.2.12479018
```

يلزم تشغيل CI بعد الدفع للتأكد من توفره فعلياً على صورة GitHub الحالية.

### حالة الأدوات المحلية

- Flutter/Dart غير مثبتين في Sandbox الحالي.
- `check_project_health.py` فحص 59 ملف Dart ونجح.
- جميع سكربتات Bash النشطة اجتازت `bash -n`.
- يوجد 23 ملف اختبار Dart.
- لا يمكن إعلان نجاح `flutter analyze` أو `flutter test` محلياً دون Flutter؛ المرجع هو GitHub Actions.

## 5. الخصوصية والأمان

### نقاط جيدة

- لا توجد Firebase dependencies في `pubspec.yaml`.
- لا توجد مراقبة تلقائية للإشعارات.
- لا توجد مراقبة تلقائية للحافظة؛ القراءة مرتبطة بإجراء المستخدم أو مسار Accessibility المصرح.
- Whisper يتحقق من الحجم وSHA-256 قبل اعتماده.
- حزم المحتوى تتحقق من الهوية والإصدار والمصدر والترخيص والهاش.
- Accessibility يتطلب تفعيلاً صريحاً وقائمة تطبيقات مسموحة.
- إعدادات R8/obfuscation موجودة لمسار release في CI.

### نقاط يجب حسمها

- `INTERNET` مطلوب للتنزيلات، لذلك يجب أن تظل الواجهة صريحة بشأن وقت الاتصال.
- يجب إضافة شاشة خصوصية قصيرة قبل تفعيل Accessibility تشرح النص المقروء، التطبيقات المسموحة، ومتى تختفي الترجمة.
- يجب منع ادعاء "محرك صوت كامل داخل التطبيق" ما دام المسار الحالي `flutter_tts`.
- يجب إزالة أو عزل Gateway ElevenLabs من المنتج النهائي إذا كان الهدف نسخة محلية خالصة.
- يجب مراجعة سياسة Google Play الخاصة بخدمات Accessibility قبل النشر العام.

## 6. التعريب

يوجد `app_ar.arb` و`app_en.arb` وتوليد Flutter localization، لكن التطبيق لا يطبق العقد كاملاً بعد:

- `feature_hub_screen.dart` يحتوي على عدد كبير من النصوص العربية الثابتة.
- توجد نصوص ثابتة في Dashboard وOverlay والخدمات.
- عدة شاشات تستخدم `Directionality(textDirection: TextDirection.rtl)` مباشرة.
- هذا يجعل الإنجليزية لا تتبع اتجاه التطبيق في كل المواضع.
- أسماء بعض الأصوات والرسائل التشغيلية ما زالت عربية داخل الخدمة.

**الأولوية:** استخراج كل النصوص المرئية إلى ARB، ثم استخدام `Directionality.of(context)` أو اتجاه MaterialApp بدلاً من فرض RTL.

## 7. خريطة الخطوات الناقصة بالترتيب

### P0 — يجب إنهاؤها قبل البناء التالي

1. دفع إصلاح اختبار localization للشطرنج.
2. دفع إصلاح NDK وتشغيل CI من جديد.
3. جعل فرعي `analyze and test` و`APK` أخضرين.
4. إضافة اختبار sound service للأصول المحلية وزر الكتم.
5. إضافة اختبار عدم انهيار `ChessClubScreen` عند غياب/تبديل locale.

### P1 — تثبيت المنتج الأساسي

1. اختبار APK على Android حقيقي: Pixel/Samsung/Xiaomi، Android 13–16.
2. اختبار الفقاعة على WhatsApp وTelegram وتطبيق لا يسمح بالوصول.
3. إضافة واجهة allowlist تعرض اسم التطبيق لا package id فقط.
4. معالجة النصوص المتعددة/المكررة في Accessibility بدلاً من اختيار أول node فقط.
5. تحسين OCR إلى العربية واللغات المطلوبة.
6. جعل مستندات/عدسة الهدف لغة يختارها المستخدم، لا لغة الجهاز إجبارياً.
7. إدخال محرك TTS محلي حقيقي مثل Piper/sherpa-onnx، مع حزم أصوات عند الطلب.

### P2 — الذكاء والقصص

1. تحديد نموذج Story AI محلي واقعي وحجمه وذاكرته.
2. بناء `LocalStoryAiService` بعقد واضح: تنزيل، تحقق، توليد، إلغاء، حذف.
3. ربط بطاقة القصص بالتوليد الفعلي بدلاً من الاكتفاء بالمحرر والمكتبة.
4. إضافة تلخيص/إعادة صياغة/اختيار نبرة محلية.
5. إضافة اختبارات تمنع ظهور نتيجة وهمية عند غياب النموذج.

### P3 — جودة الإصدار

1. إزالة النصوص الثابتة والتعريب الكامل.
2. اختبار RTL/LTR وإمكانية الوصول وحجم الخط.
3. بناء release APK/AAB موقّع خارج المستودع مع R8 والتحقق من obfuscation.
4. فحص حجم APK وتكلفة كل نموذج.
5. فحص البطارية والذاكرة، خاصة Whisper وAccessibility polling.
6. إضافة صفحة سياسة الخصوصية وشروط استخدام Accessibility.
7. تنظيف scripts وpatches القديمة من جذر المستودع أو نقلها إلى `tools/archive`.

## 8. تعريف "جاهز للإصدار"

لا نعتبر النسخة جاهزة إلا عند تحقق الشروط التالية:

- CI للتحليل والاختبارات وAPK أخضر.
- اختبار حقيقي للترجمة والحوار على جهاز Android.
- اختبار Accessibility على جهازين على الأقل مع تطبيقين مسموحين وتطبيق غير مسموح.
- لا توجد نصوص مرئية غير مترجمة في المسارات الرئيسية.
- TTS المحلي الحقيقي يعمل بدون أصوات Android المثبتة، أو يتم تغيير الوصف ليقول بوضوح إنه TTS نظامي.
- كل بطاقة تعرض حالة صادقة: عاملة، تحتاج تنزيل، غير متاحة، أو تجريبية.
- لا يوجد cloud service يعمل دون موافقة واضحة.
- release build مموّه ومختبر، مع حفظ المفاتيح خارج APK.

## 9. القرار المقترح

الخطوة الصحيحة التالية ليست إضافة بطاقة جديدة. الترتيب الأنسب هو:

1. **إغلاق CI الحالي.**
2. **اختبار الفقاعة على هاتف حقيقي.**
3. **تنفيذ TTS المحلي.**
4. **إكمال OCR والتعريب.**
5. **بناء Story AI المحلي.**
6. بعد ذلك فقط مراجعة PRO والفيديو والنشر.
